section. Publish the new library and shared script before distributing standalone
ports. HoloGui must precede Ariente, which must precede ArienteWorld.

## Native APIs

* Registry entries receive native ID-bearing block/item properties before
  construction. Item definitions, equipment assets, resource metadata,
  identifiers, data generators and dimension/environment data use 26.1.2 formats.
* Block entities and entities use ValueInput/ValueOutput while retaining the
  existing named data inside saves. Prototype loading and saving use the caller-supplied registry context before a
  block entity has a Level. Custom item state uses copy-on-write components and registry-aware
  item/fluid codecs. SavedData has native codecs and namespaced IDs. Before the first lookup,
  legacy root-level files are copied atomically into the matching namespace
  folder. Existing modern files take precedence and original files are retained.
  This covers power/security IDs, wireless channels, area locks, city AI and scouts.
* Native item, fluid and energy capabilities use NeoForge transactions. The
  grouped storage adapter journals its contents and counters across nested/root
  commit and rollback; older internal inventory interfaces remain behind adapters.
* Recipes use native inputs, codecs and server recipe access. Purifying recipes
  are explicitly synchronized for the client's JEI view and cleared on logout.
* Client rendering follows extraction and deferred submission. Holographic widgets
  freeze geometry and item render states during extraction and preserve draw order
  through nested item/special-model submits. Text carries explicit ARGB alpha.
* Block/entity models, connected textures, OBJ textures, custom item models,
  powersuit geometry/equipment and custom pipelines use native rendering APIs.
  Empty forcefields skip submission. Global displays and forcefields retain the
  camera-relative world transform and restore render state afterward.
* Live cameras use an isolated native level render state and texture target,
  restoring the main camera, target, projection, fog and level state. Perspective
  cameras submit frozen geometry. The Ariente sky uses the native custom skybox
  renderer and extracted sky/environment data.
* Worldgen retains registry IDs, authored city parts and generation algorithms.
  The removed random-patch feature is replaced with a registered implementation
  retaining its original placement/random sequence. Flying mobs retain the old
  flying movement rules; scout tickets use native registered ticket types and
  shared chunk leases.

## Manual coverage still needed

This is a development port. Automated checks do not replace a full survival
playthrough, sustained city-AI/balance testing, multiplayer interaction or a
human pass through text entry, dragging and other GUI controls. Third-party
renderer/shader-pack compatibility has not been checked on 26.1.2. Historical
Forge fixtures and `PORT_1_21.md` retain their original scope; they are not claims
that those entire suites have been migrated to this branch.

## IntelliJ startup follow-up

Direct IntelliJ startup exposed a mutable shared NeoGradle asset directory and
built mod jars competing with live sources. The shared script now retains and
tracks a versioned asset directory, uses matching client/datagen arguments,
resolves included runtime projects to class directories and supplies transitive
local sources to development runs. All 4,750 indexed asset files were verified,
including their SHA-1 hashes. The actual IntelliJ **Workspace: Client** launch
reached the main menu with 14 mods and no startup errors or duplicate mod
selections. The workspace build, standalone companion build and runtime-resolution checks
also pass. Removing an isolated asset invalidates preparation and restores the
correct file automatically; this was checked against its SHA-1 hash.

## Live camera and tank rendering follow-up (2026-11-09)

The native terrain shaders also read the camera origin from the global settings
uniform. Each live feed now binds its own global settings buffer with the mounted
lens position and target dimensions, then restores the previous buffer. It no
longer inherits the player's camera origin. The buffer is disposed with the feed.
Translucent Ariente render types now sort their quads on upload, allowing the tank
beam and glass to draw in depth order instead of the glass hiding the beam.

The tutorial has a dedicated pixel regression. With all workspace mods loaded,
Fancy and Fabulous both pass: a fixed live-camera image remains pixel-identical
(mean difference 0.0) after player strafing, distance, height and yaw changes;
both eight-section beams are visible at all 24 probes per column from front and
both diagonal views, and at zero probes when disabled. Representative images
were also inspected. Tests use disposable worlds under `/var/tmp`; the installed
Tutorial save is preserved. See the README for `-Ptutorial_render_regression`.
These are repairs to the unreleased 26.1.2 port; no release version was changed.

The live lens also samples environment attributes at its mounted position and
retains Minecraft's normal projection distance so sky geometry is not clipped
by the shorter terrain capture radius. Its culling frustum still limits terrain
to the configured capture range. The lens reports a detached camera so Minecraft
includes the local player's body when it is visible, including while the player
uses first-person view. The normal player camera mode is preserved.

Feed refreshes run after the main world finishes rendering. Rendering a feed
inside block-entity extraction could invalidate the outer iterator when the
nested extraction removed a stale globally rendered block entity; a Fabulous
test exposed this while changing the camera fixture.

All 13 tutorial regression scenes pass with both Fancy and Fabulous, loading
the complete workspace and its local dependency sources. The added checks cover
daytime sky and sun/cloud geometry, nighttime sky and celestial geometry, and
the local player in first-person and third-person mode. Both entity extraction
and chestplate pixels confirm that the player appears only inside the mounted
camera's view. The existing movement and tank checks still pass. Screenshots
and logs are retained under `build/verification/live-camera-scene-26.1.2/`.
